# Contribuir

Cada cambio de comportamiento debe identificar la fuente o el problema que resuelve y añadir un caso reproducible. Para contratos y modelos, actualizar primero el esquema, regenerar y ejecutar los casos comunes en Go y Python.

No incorporar código, plantillas ni suites de proyectos de referencia. Escribir los casos desde especificaciones y evidencia autorizada. Usar datos sintéticos; no subir credenciales, certificados de uso real ni información personal.

No regenerar resultados esperados para ocultar una regresión. Documentar la razón de un cambio de contrato, código de error o interpretación normativa. Los ejemplos de red deben distinguir pruebas locales, servicios simulados y conexiones reales.

Antes de entregar: ejecutar generación en modo comprobación, tests Go/Python y validación de paquetes. Las instrucciones están en README.md. Mantener cambios de fuentes oficiales separados de actualizaciones automáticas del comportamiento.
